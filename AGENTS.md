# Контрольная панель

Управляй выбранным экземпляром через scripts/control.py. При работе из другого
cwd используй абсолютный путь программы. Если контракт экземпляра ещё не прочитан, прочитай
docs/control-entry.md; известный контракт повторно читать не нужно. Пути показывает environment. Выбирай state/config/bindings до записи данных.

Запускай только задачи, явно выбранные пользователем. «Открой задачи» — одна
команда open ID…; покажи статус и цель, не жди исполнителя. Его сообщение
начинай с TASK_ID: . Вне herdr укажи --herdr-session NAME.

Читай только нужный skills/control-ИМЯ/SKILL.md: для списка — list;
для проекта — project;
для создания/правки задачи — task; для запуска — start; для прогресса, вопросов, результата
и агентского ревью (включая pending auto) — review; для памяти — memory; для сверки — sync;
для приёмки/отмены по поручению пользователя — complete.

План покажи в чате и сохрани до работы по docs/planning.md. Исполнитель читает
assignment.md и docs/worker.md, сохраняет артефакты и результат через finish.
Самостоятельный finish оставляет review; complete требует поручения пользователя.

Изменения кода выполняй в worktree задачи (--code); чтение и применение готовых
настроек — --no-code. Постоянные настройки хоста ссылаются на исходный checkout.
Рабочие инструкции и отчёты по умолчанию на русском. Сообщения коммитов пиши
на английском: конкретно описывай суть изменения. При приёмке с созданием
коммита передавай такое сообщение через complete --commit-message.
Секреты сохраняются в штатном хранилище CLI провайдера, вне заданий и памяти панели.
