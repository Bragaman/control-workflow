# Сверка состояния

Если контракт экземпляра ещё не прочитан, читай
[control-entry.md](../../docs/control-entry.md).
Сверка запускается по запросу, без расписания. По умолчанию охват — все проекты
и ресурсы, описанные в панели; если указан проект, ограничь обход им и его
зависимостями. Проверенные факты записывай сразу, неоднозначности уточняй в чате.

## Обход

1. Покажи и сохрани план по `docs/planning.md`. Если работа идёт в запуске,
   прочитай его assignment, план и checkpoint по `docs/worker.md`.
2. Получи краткий список `projects`. Для каждого выбранного проекта прочитай
   `show projects ID` и `tasks --project ID --all` (включая принятые задачи).
   Составь список источников из описания, репозиториев, документации, релевантной
   памяти и ссылок в задачах. Ищи файлы через `rg --files` и тему через
   `memory-list --project ID --query 'тема'`; подробные задачи, отчёты и память
   читай только для нужной проверки. При полном обходе учти также общие документы
   панели и ресурсы без привязки к проекту; сохраняй эту привязку как вопрос.
3. Веди реестр охвата: проект, задача/ресурс, где описан, чем проверять, результат.
   Документированный ресурс без доступной проверки получает строку «непроверено»,
   а не исчезает из отчёта. Новые зависимости добавляй в реестр по мере обхода.
4. Выполни проверки чтения по [references/checks.md](references/checks.md).
   Для каждого существенного вывода зафиксируй время с часовым поясом, источник
   (путь/команда/endpoint без секретов), наблюдение и предел вывода. Статус из
   JSON — факт о записи панели; старый отчёт — последнее известное состояние,
   а не текущая проверка ресурса.
5. Сопоставь наблюдения с записями и сразу внеси однозначные исправления по
   правилам ниже. Для конфликта источников укажи оба, задай конкретный вопрос
   пользователю и продолжай независимые проверки. Ответ требуется до зависимой
   правки. Недоступность, таймаут и запрет доступа отмечай как «непроверено» с
   причиной; сохраняй последний подтверждённый факт и его дату.
6. Покажи в чате охват, изменения, состояние ресурсов, непроверенные пункты и
   вопросы. Сохрани реестр источников и отчёт по `docs/worker.md`; с RUN_ID
   используй progress, а готовую сверку передай в review через finish.
   Незаконченные зависимые изменения опиши в checkpoint; block применяется
   при просьбе пользователя отложить вопрос.

## Актуализация

В каждом проекте обновляй одну сводку `STATE_ROOT/status/PROJECT_ID.md` выбранного экземпляра:
текущее наблюдение, последнее подтверждённое состояние, источники, время,
расхождения, вопросы и внесённые изменения. Общие ресурсы — `STATE_ROOT/status/shared.md`.
Подробный реестр можно хранить в запуске и ссылаться на него из сводки.
Это административные артефакты; JSON проектов, задач, запусков и памяти меняются
только через CLI панели. Перед записью перечитай изменяемый факт: если источник
или запись изменились во время обхода, проверь заново.

| Объект | Действие по подтверждённому факту |
| --- | --- |
| Описание проекта | `project-set`, меняя только проверенное поле. Привязка workspace требует подтверждения личности workspace и намерения пользователя. |
| Неактивная задача | `task-set` для фактических уточнений цели/критериев с сохранением намерения пользователя. Смена намерения, отмена или новая задача требуют уточнения. |
| Задача running/blocked | Сохрани наблюдение в сводке и памяти. task-set для неё запрещён командой. progress используй для текущего запуска сверки, а не чужого исполнителя. |
| Расхождение task/run или исчезнувший исполнитель | Покажи обе записи и наблюдение; предложи восстановление. Сверка не выполняет open/start, answer, interrupt или recover-start. |
| Проверенное знание | Найди прежний факт через memory-list; добавь изменившийся факт через memory-add с источником, временем, условиями применимости и ссылкой на заменённую запись. |
| Документация ресурса | Исправь подтверждённые поля и дату/источник проверки. Доменные инструкции бери из источников выбранного проекта. Планы отличай от созданных ресурсов. |

Для memory-add с текущим RUN_ID проект должен совпадать с проектом запуска
(исключение — shared). Знания других проектов сохраняй без --run, но со ссылкой
на отчёт сверки. finish уже сохраняет отчёт в память: отдельно его не дублируй.

При повторном обходе сначала прочитай сводку и найди предыдущую запись памяти
для того же объекта и свойства. Сравни смысл факта и условия применимости,
исключая дату повторной проверки. Если они прежние, обнови время и источник
в сводке, сохрани ID памяти и не вызывай memory-add/task-create. При изменении
добавь заменяющую запись с прежним ID; при возвращении к старому состоянию
это новый переход, а не основание использовать устаревшую запись. Если
невозможно понять, какая запись актуальна, вынеси конфликт в вопрос.

Изменения отслеживаемой документации других репозиториев выполняй только
в worktree задачи. При его отсутствии сохрани предлагаемый diff в запуске и
запроси нужный worktree; независимые административные обновления продолжай.
Конфигурация/рестарт служб, создание/удаление ресурсов, приёмка задач и
Git-публикация находятся вне сверки. Обнаруженный работающий ресурс сам по себе
не даёт основания для done или review другой задачи: принятие остаётся за
приёмщиком, отчёт исполнителя — за его запуском.

Сверка завершена, когда каждому объекту реестра назначен проверенный результат,
непроверенность с причиной или вопрос; внесённые исправления перечитаны, а
оставшиеся зависимые правки явно перечислены. Непроверенные источники допустимы
в результате сверки, но выводы о них не выдаются за подтверждённые.
