# Инструкции исполнителю

Выполняй только цель и критерии из assignment.md. Начни с чтения проекта,
выборки нужной памяти и сохранённых вопросов/прогресса предыдущего запуска.
Не загружай всю память. Для оперативных уточнений и координации используй
чат и доступные прямые сообщения агентам. Файлы нужны для сохраняемого
контекста, артефактов, отложенной работы и передачи другому исполнителю;
способ общения выбирай по задаче. Сообщение не заменяет сохранение результата
или изменение статуса через команду панели.
Используй полную команду панели из assignment.md: путь control.py и параметры
state/config/bindings. Текущий каталог может быть worktree; он не выбирает экземпляр.

До выполнения прочитай [planning.md](planning.md) из ресурсов программы: план
показывай сразу в чате и сохраняй перед работой, откладыванием или передачей.
Приступая к задаче, прочитай её сохранённый план по правилам этого документа.

Код меняй только в перечисленных worktree. Если понадобился другой репозиторий,
запроси его у пользователя в чате. Не редактируй исходные деревья репозиториев.
Сохрани проверенный код и отчёт через finish для review. Приёмка и закрытие
по явному поручению пользователя — через complete из своего таба;
до вызова прочитай [control-complete](../skills/control-complete/SKILL.md)
и [git-policy.md](git-policy.md). Артефакты продолжения храни в запуске панели:
worktree в режиме branch с origin удаляется после push.
Для применения существующих настроек на хост запускай установщик из исходного
репозитория: постоянные ссылки должны вести туда. Worktree нужен для изменений
отслеживаемых файлов; если таких изменений нет, работай без него. Если они стали
необходимы в задаче без worktree, запроси репозиторий и worktree в чате до редактирования.
Во время работы сохраняй полезные промежуточные артефакты после значимых
этапов: принятых решений, изменений, проверок или получения результатов
исследования. Перед паузой или передачей сохрани состояние и следующий шаг.
Используй файлы запуска для отчётов, исходных данных и checkpoint, а progress
для краткого состояния работы. Обновляй существующий артефакт, если отдельная
версия не нужна для проверки или восстановления; отдельный файл для каждого
сообщения или команды не требуется.

```sh
python3 /path/control_plane/scripts/control.py --state-root /path/state progress --run RUN_ID --text 'Что сделано и следующий шаг'
python3 /path/control_plane/scripts/control.py --state-root /path/state memory-list --project PROJECT_ID --query 'Нужная тема'
python3 /path/control_plane/scripts/control.py --state-root /path/state memory-add --project PROJECT_ID --run RUN_ID --kind decision --title 'Решение' --file /path/decision.md
```

Решение содержит: контекст, выбранный вариант, причины, последствия, ссылки
на задачу/изменения. Знание содержит проверенный факт и условия применимости.
Если новое решение заменяет старое, укажи ID прежней записи и что изменилось.
Не сохраняй секреты и полные логи без необходимости.

Если нужен ответ, задай вопрос прямо в текущем чате пользователя. Если доступен
инструмент вопросов, используй его. Пока ждёшь, выполняй независимую работу;
шаги, зависящие от ответа, продолжай после его получения. Сам вопрос не требует
block или questions.json. Обычный прогресс работы сохраняй как прежде.

Если пользователь просит отложить вопрос или обсуждение, сохрани точный вопрос
и checkpoint для следующего взаимодействия: выполненные шаги, неоконченные
изменения, проверки, следующий шаг. Используй block и заверши ход. Уведомление
будет отправлено командой; даже при сбое уведомления запись останется.

```sh
python3 /path/control_plane/scripts/control.py --state-root /path/state block --run RUN_ID --question 'Что уточнить?' --checkpoint 'Где остановился и как продолжить'
```

block сохраняет checkpoint.md и его путь в questions.json.
После block не жди ответа в цикле и не продолжай работу автоматически.
При следующем взаимодействии покажи отложенный вопрос прямо в чате.
Управляющий агент сохранит ответ через answer, снимающий блокировку текущего
запуска. По поручению пользователя продолжай следующим ходом в том же табе,
с тем же RUN_ID и worktree; прочитай questions.json этого запуска и checkpoint.
Если исполнитель исчез, сначала проверь состояние и восстанови его из файлов.
Самостоятельный finish оставляет review. Приёмку и Git-публикацию через complete
выполняй только после явного поручения пользователя завершить задачу.

После каждого задания покажи результат прямо в текущем чате: что получилось,
основные выводы или изменения, как проверено, ограничения и вопросы.
Ссылки на файлы дополняют содержательный ответ; пользователь должен понимать
результат без открытия отчёта. Для большого исследования изложи основные
выводы и рекомендацию в чате, подробности оставь в артефакте.

Сохрани итоговые артефакты даже при отмене задания или неудачной попытке:
полезные результаты, выполненные проверки, причину остановки и оставшиеся
шаги. Объём выбирай по значимости работы; для короткого административного
действия достаточно записи состояния панели или краткой записи в памяти.
Для работы без RUN_ID используй memory-add без --run. Повторно сохранять
неизменённый отчёт после просмотра или копировать переписку целиком не нужно.

По завершении запуска подготовь Markdown-отчёт: что сделано, как, изменённые файлы/
ветки, команды проверок и их результаты, ограничения и оставшиеся вопросы.
Отдельно зафиксируй решения с причинами, если они появились. Отчёт и решения
можно сначала записать рядом с assignment.md, затем передать команде:

```sh
python3 /path/control_plane/scripts/control.py --state-root /path/state finish --run RUN_ID --report /path/report.md --decisions /path/decisions.md
```

`--decisions` необязателен. finish сохраняет отчёт в запуск и память проекта,
переводит работу в review и уведомляет о готовности к приёмке.
Сохранение артефактов не означает приёмку пользователем. При отмене или
незавершённой работе сохраняй checkpoint; finish используй для результата,
готового к review.
