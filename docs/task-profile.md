# Выбор типа, сложности и модели

При создании и перед новым запуском выбери тип по основной работе:
implementation — реализация и диагностика с исправлением; research — исследование;
reasoning — анализ; planning — планирование. Реализация готового плана остаётся
implementation. Worktree выбирается отдельно по необходимости менять код.

normal подходит задаче с понятными границами и обычной проверкой. complex выбирай
при неопределённости требований или поведения системы, связанных изменениях
нескольких компонентов или противоречивых ограничениях, требующих проверки
гипотез и последствий. Количество файлов само по себе сложность не определяет.

Базовая переносимая политика задаёт Sol medium для normal и Sol high для complex
во всех типах. Для исключения выбери именованный профиль и кратко запиши причину
в плане до запуска.

| Профиль | Модель / effort | Когда выбирать |
| --- | --- | --- |
| luna | gpt-6-luna / medium | Извлечение, классификация, шаблонные преобразования с однозначной проверкой |
| terra | gpt-6.1-terra / medium | Текст по готовым материалам, изображения, интерфейсы, небольшие исправления с ясными границами |
| sol | gpt-6.1-sol / medium | Разработка, диагностика, инфраструктура |
| sol-high | gpt-6.1-sol / high | Миграции, сложная диагностика, несколько связанных компонентов |
| astra | gpt-6-astra / medium | Особенно сложные задачи с неоднозначностью и множеством ограничений, включая код и исследования |

Тип implementation/normal сам по себе не выбирает Terra; complex не включает
Astra автоматически. Выбор делает управляющий. Это стартовые рекомендации:
сравнивай качество, число доработок, время и расход клиента на сопоставимых задачах.
Цены API не отражают расход подписки.

При создании/правке используй --profile NAME; для одного нового запуска —
open TASK --profile NAME. Перед запуском сверь выбранную политику через environment.
Старый config без политики сохраняет прежнюю матрицу и может использовать
model=default. При подключении, местных изменениях или миграции читай
[model-policy.md](model-policy.md). Работающий исполнитель сохраняет свою модель;
смена требует checkpoint и явного нового запуска. Доступность модели и effort
проверяется в клиенте; панель не подменяет модель при отказе.
