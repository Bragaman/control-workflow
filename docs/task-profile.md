# Профиль задачи

При создании или перед новым запуском выбери --task-kind по основной работе:
research — исследование, reasoning — анализ, planning — планирование,
implementation — реализация. Обычная диагностика и исправление —
implementation/normal; сложный анализ взаимосвязей — --complexity complex.
Реализация готового плана остаётся implementation независимо от сложности.
Раздели смешанные этапы, если им нужны разные исполнители.

Для Codex по умолчанию выбирай Sol или другую более экономную модель, чем Astra.
Astra используй только для крупного исследования, явно запрошенного пользователем.
«Посмотри, что не работает», поиск причины сбоя и исправление — обычная
диагностика для Sol; не превращай её в research ради выбора Astra.
Небольшое исследование, планирование или сложность complex сами по себе
не дают основания выбирать Astra.

Модель и effort берутся из выбранной конфигурации; worktree не влияет на
профиль. Перед запуском проверь модель выбранного профиля: model=default
оставляет выбор CLI и не гарантирует Sol. Подбери конфигурацию с экономной
моделью, если условия для Astra не выполнены; тип задачи сохраняй по сути работы.
Изменение типа/сложности через task-set применяется к следующему
запуску, модель работающего исполнителя сохраняется.
