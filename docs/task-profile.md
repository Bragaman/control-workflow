# Профиль задачи

При создании или перед новым запуском выбери --task-kind по основной работе:
research — исследование, reasoning — анализ, planning — планирование,
implementation — реализация. Обычная диагностика и исправление —
implementation/normal; сложный анализ взаимосвязей — --complexity complex.
Реализация готового плана остаётся implementation независимо от сложности.
Раздели смешанные этапы, если им нужны разные исполнители.

normal подходит задаче с понятными границами и обычной проверкой. complex выбирай
при неопределённости требований или поведения системы, связанных изменениях нескольких компонентов
или противоречивых ограничениях, требующих проверки гипотез и последствий.
Количество файлов само по себе сложность не определяет.
Сложная диагностика с исправлением остаётся implementation/complex.
Для research/complex требуется явно запрошенное крупное исследование:
несколько направлений, разнородные источники или данные и синтез выводов.
Сложный анализ без такого исследования — reasoning/complex.

Для Codex по умолчанию выбирай Sol или другую более экономную модель, чем Astra.
Astra используй только для крупного исследования, явно запрошенного пользователем.
«Посмотри, что не работает», поиск причины сбоя и исправление — обычная
диагностика для Sol; не превращай её в research ради выбора Astra.
Небольшое исследование, планирование или сложность complex сами по себе
не дают основания выбирать Astra.

Модель и effort берутся из выбранной конфигурации; worktree не влияет на
профиль. Перед запуском проверь модель выбранного профиля: model=default
оставляет выбор CLI и не гарантирует Sol. Подбери конфигурацию с экономной
моделью, если условия для Astra не выполнены; тип задачи сохраняй по сути работы.
Изменение типа/сложности через task-set применяется к следующему
запуску, модель работающего исполнителя сохраняется.

Местную матрицу моделей и effort храни во внешнем config, а критерии выбора —
в правилах экземпляра с указателем из его AGENTS.md. Переносимые defaults
не гарантируют экономную модель. Перед запуском сверь все восемь сочетаний
типа/сложности с местной политикой через выбранный config.

Для узкой повторяемой операции с проверяемым результатом допустим отдельный
конфиг, например с Luna high. Скопируй основной внешний config и измени только
нужный профиль; передай его путь через --config при создании и запуске задачи.
Запиши причину исключения и выбранные модель/effort в плане. Частичный JSON
объединяется только с defaults программы: остальные профили могут вернуться
к model=default вместо настроек основного внешнего config. Учитывай это при проверке исключения.
Тип и сложность сохраняй по сути работы. Для возврата явно выбери основной config.
Автоэскалации нет; наличие модели и доступ к ней проверяются отдельно.
