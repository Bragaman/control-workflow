# Восстановление запуска

При action=error прочитай state.json и launcher.log указанного запуска.
Состояние launching с работающим подготовителем означает ожидание старта.
Проверяй namespace и pane, сохранённые в запуске.
Другой namespace требует явной сверки и перепривязки; чужой исполнитель
не подтверждает принадлежность терминала задаче.

После создания layout панель до 10 секунд ждёт, пока shell останется единственным
процессом foreground job (не дольше agent_start_timeout_ms). Ожидание читает
pane process-info и не отправляет команды в терминал. Если shell не готов,
запуск остаётся launch_failed без agent_start_intent; работающий процесс не прерывается.

После ошибки agent start подготовитель повторяет проверку namespace, агента и
пути assignment в терминале (до трёх чтений с паузой 0,25 секунды). Подтверждённый
исполнитель продолжает running; ошибка команды остаётся в startup_error.
Если исполнитель жив, но путь задания пока не виден, или проверка недоступна,
запуск остаётся launching с startup_confirmation_pending=true. Это неизвестный
исход старта, даже если launcher_alive=false. Прочитай startup_error и повтори
open выбранной задачи после восстановления доступа или появления задания:
подтверждение продолжит тот же запуск без нового start/prompt. При отсутствии
подтверждения open вернёт ошибку и сохранит состояние. Не считай launching без
подготовителя разрешением на повторную отправку задания.

Отсутствие агента, подтверждённое последней проверкой после повторных чтений,
оставляет launch_failed и уведомление об ошибке. Ошибки до agent start, например
неудачное создание layout, также остаются launch_failed. Более свежие progress,
blocked или review исполнителя сохраняются при завершении подготовителя.

В Herdr поле agent у обычного shell может отсутствовать или быть null. Панель
принимает оба варианта после проверки pane_id; некорректный ответ остаётся
неизвестным исходом. Структурированный agent_pane_busy означает отказ до отправки
команды агенту. Если подготовитель завершился и отсутствие агента подтверждено,
open может создать новый запуск. Это применимо и к старому launching/pending,
оставшемуся после такого отказа. Если в прежнем pane уже появился агент с путём
задания этого запуска, open восстанавливает тот же запуск без нового prompt.

Таймаут agent start не доказывает отсутствие агента. Если в сохранённой панели
работает агент выбранного адаптера и виден абсолютный путь assignment.md этого запуска, выполни
`recover-start --run RUN_ID`. Команда проверяет отсутствие работающего подготовителя,
наличие агента и путь задания, сохраняет startup_error и продолжает тот же запуск без
повторного prompt. Неизвестный исход layout требует ручной сверки; повторять
create/start вслепую нельзя. Намерения сохранены в layout_intent и agent_start_intent.

После исчезновения исполнителя open создаёт новый запуск только после проверки
отсутствия прежнего. Worktree и план сохраняются; предыдущий checkpoint читается
до работы. Перед interrupt подтверди остановку исполнителя и подготовителя.

Перед `git worktree add` кодовый запуск сохраняет worktree_intent. При повторном
open панель сверяет найденный каталог с регистрацией Git и веткой; если каталог
и ветка отсутствуют, намерение можно безопасно повторить. При расхождении она
останавливается, сохраняя Git и состояние для сверки. После таймаута worktree
open панель проверяет список worktree в сохранённом родительском workspace и
повторяет открытие только при подтверждённом отсутствии открытого workspace.
Если workspace уже открыт или список неполон, автоматического присвоения ему
исполнителя нет: нужна ручная сверка. При неизвестном исходе создания родительского
workspace также требуется ручная сверка; не повторяй создание вслепую.

После сверки в сохранённом namespace подтверди найденный родительский workspace
через `recover-layout --run RUN --workspace ID`. Для созданного дочернего workspace
добавь `--pane ID`: команда принимает только единственную панель без агента и
проверяет соответствие пути Git worktree и ID workspace. Затем выполни open
выбранной задачи. Команда не запускает агента и не закрывает layout. При других
панелях, агенте или несовпадении репозитория восстановление отклоняется.
Если run уже сохранил панель, но снятие layout_pending не удалось, укажи те же
workspace и pane: команда сверит также сохранённый tab и завершит запись журнала.
Повтор подтверждения безопасен. Для исчезнувшего родителя можно подтвердить новый
основной workspace; старая привязка заменяется только после workspace_not_found.
Таймаут, ошибка доступа и существующий старый workspace запрещают замену.
`interrupt TASK --reason 'Подтверждение остановки'` сохраняет старый
запуск и переводит задачу в ready; процессы эта команда не останавливает.

Ожидающий ответа blocked возвращает вопрос и checkpoint. Ответ сохраняй через
`answer TASK --text 'Ответ'`, затем по поручению продолжай тот же запуск в том же
табе. Ответ не отправляет новый ход. Протокол вопросов — в [questions.md](questions.md).
Если исполнитель исчез, восстанавливай его по сохранённым файлам отдельно;
исчезновение процесса не означает готовность результата.

При аварии между обновлениями task/run сравни оба JSON: запись запуска пишется
первой. При переносе программы сохраняй её путь или явно обновляй выбранную
установку: старые assignment и launch_argv остаются историей конкретного запуска.

Если task находится в ready, а её active_run — в review, прочитай result.md,
checkpoint и более поздние отчёты запуска. Для восстановления сохранённого
результата выполни `recover-review --run RUN_ID`. Команда проверяет принадлежность
текущего запуска задаче, статус review, непустой result.md и отсутствие работающего
подготовителя. Она возвращает task в review, сохраняя run, отчёты и агентские
ревью без изменений; запись восстановления остаётся в review-recovery.json.
Повторный вызов безопасен. Приёмка по-прежнему требует поручения пользователя
и отдельной команды complete с назначенным reviewer.

Возврат из review через `task-set --status ready` или `--status backlog` переводит
прежний run в interrupted, сохраняя его результат. Для доработки продолжи
выбранную задачу через open по поручению пользователя. Такой run восстановить
через recover-review нельзя. `task-set --status cancelled` из review также
помечает run как cancelled; для отмены с закрытием таба используй
`complete TASK --status cancelled`.
