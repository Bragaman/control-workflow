# Приёмка и сохранение кода

Самостоятельный finish сохраняет отчёт и оставляет review. Просьба пользователя
принять или завершить задачу даёт полномочия выполнить complete и предусмотренные им Git-операции.
Принимает назначенный reviewer, по умолчанию user; это договорённость, не аутентификация.
При явном делегировании назначенному приёмщику передай --by REVIEWER;
самостоятельно назначать делегирование нельзя.
Перед complete из таба исполнителя сохрани отчёт и покажи результат в чате:
таб может закрыться сразу.

Git-режим выбирается в task-create или task-set через --git-mode main|branch.
Значение по умолчанию для новых задач находится в config/defaults.json и может
быть переопределено пользовательским config.json. Старые задачи без поля используют main.
Для отдельной ветки/PR выбирай branch, иначе main.

| Режим | Операция complete | Worktree |
| --- | --- | --- |
| main | Коммит изменений, merge временной ветки в основную; push основной при origin | Сохраняется |
| branch с origin | Коммит, push ветки, проверка remote commit; merge выполняет пользователь | Удаляется после push |
| branch без origin | Коммит, локальный merge в основную | Сохраняется |

Для создания коммита из несохранённых изменений передай
`complete TASK --commit-message 'Preserve worktrees when pushing fails'`.
Сообщение должно быть на английском и конкретно описывать суть изменения;
одного ID задачи или сообщения «задача завершена» недостаточно.
Без непустого сообщения complete оставляет изменения и задачу в review до commit/merge/push.
Язык и содержательность проверяет приёмщик; CLI проверяет наличие сообщения.
Одно сообщение применяется ко всем новым коммитам задачи в её репозиториях.
Если изменения уже закоммичены, параметр не нужен; существующие коммиты сохраняются.
При повторе после ошибки push сообщение уже созданного коммита не меняется.
Для merge-коммита панель использует `Merge: ` и заголовок коммита задачи.

Основное дерево перед merge должно быть чистым и на основной ветке. Конфликт
отменяет только попытку merge панели. Незавершённые чужие Git-операции сохраняются.
Force push и принудительное удаление не выполняются. Ошибка commit/merge/push
оставляет review, таб и worktree; исправь причину и повтори complete.
Выполненные действия сохраняются в git_completion, git-completion.json и
git-completion.md запуска. После начала операции её режим менять нельзя.

`complete TASK --status cancelled --note 'Причина'` сохраняет работу и закрывает
таб без Git-публикации и удаления worktree. Перед отменой сохрани checkpoint.
`accept TASK` — низкоуровневая смена статуса без Git и закрытия таба.
`task-set --status done` запрещён. Для полного завершения используй complete.

Complete проверяет namespace, workspace, сохранённую панель и других агентов.
Если в табе есть работа пользователя, согласуй перенос или закрытие.
Из панели исполнителя запрос выполняет отдельный процесс; из другой панели
того же таба вызов отклоняется. Из управляющего таба операция синхронная.
completion_requested означает принятие запроса; итог — в completion-request.json
и state.json. При failed или исчезновении процесса повтори complete после
проверки причины. done с cleanup.status=failed требует повторного complete
с тем же итоговым статусом; закрытый таб обрабатывается повторно без ошибки.
Workspace проекта и другие табы остаются доступными.
