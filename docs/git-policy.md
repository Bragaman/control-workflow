# Приёмка и сохранение кода

Самостоятельный finish сохраняет отчёт и оставляет review. Просьба пользователя
принять или завершить задачу даёт полномочия выполнить complete и предусмотренные им Git-операции.
Принимает назначенный reviewer, по умолчанию user; это договорённость, не аутентификация.
При явном делегировании назначенному приёмщику передай --by REVIEWER;
самостоятельно назначать делегирование нельзя.
Перед complete из таба исполнителя сохрани отчёт и покажи результат в чате:
таб может закрыться сразу.

Git-режим выбирается в task-create или task-set через --git-mode main|branch.
Значение по умолчанию для новых задач находится в config/defaults.json и может
быть переопределено пользовательским config.json. Старые задачи без поля используют main.
Для отдельной ветки/PR выбирай branch, иначе main.

| Режим | Операция complete | Worktree |
| --- | --- | --- |
| main | Коммит изменений, merge временной ветки в основную; push основной при origin | Сохраняется |
| branch с origin | Коммит, push ветки, проверка remote commit; merge выполняет пользователь | Удаляется после push |
| branch без origin | Коммит, локальный merge в основную | Сохраняется |

Публикация ветки не создаёт PR и не проверяет его ревью. При удалении worktree
Git удаляет и игнорируемые файлы внутри него; нужные данные заранее сохрани вне
worktree. В остальных режимах worktree сохраняется.

Для создания коммита из несохранённых изменений передай
`complete TASK --commit-message 'Preserve worktrees when pushing fails'`.
Сообщение должно быть на английском и конкретно описывать суть изменения;
одного ID задачи или сообщения «задача завершена» недостаточно.
Без непустого сообщения complete оставляет изменения и задачу в review до commit/merge/push.
Язык и содержательность проверяет приёмщик; CLI проверяет наличие сообщения.
Одно сообщение применяется ко всем новым коммитам задачи в её репозиториях.
Если изменения уже закоммичены, параметр не нужен; существующие коммиты сохраняются.
При повторе после ошибки push сообщение уже созданного коммита не меняется.
Для merge-коммита панель использует `Merge: ` и заголовок коммита задачи.

Основное дерево перед merge должно быть чистым и на основной ветке. Конфликт
отменяет только попытку merge панели. Незавершённые чужие Git-операции сохраняются.
Force push и принудительное удаление не выполняются. Ошибка commit/merge/push
оставляет review, таб и worktree; исправь причину и повтори complete.
Выполненные действия сохраняются в git_completion, git-completion.json и
git-completion.md запуска. После начала операции её режим менять нельзя.

`complete TASK --status cancelled --note 'Причина'` сохраняет работу и закрывает
терминал задачи без Git-публикации и удаления Git worktree. Перед отменой сохрани checkpoint.
`accept TASK` — низкоуровневая смена статуса без Git и закрытия таба.
`task-set --status done` запрещён. Для полного завершения используй complete.

Complete проверяет namespace, workspace и сохранённую панель. Любая чужая
панель в табе, включая shell без агента, останавливает закрытие.
Из панели исполнителя запрос выполняет отдельный процесс; из другой панели
того же таба вызов отклоняется. Из управляющего таба операция синхронная.
completion_requested означает принятие запроса; итог — в completion-request.json
и state.json. При failed или исчезновении процесса повтори complete после
проверки причины. done с cleanup.status=failed требует повторного complete
с тем же итоговым статусом. Подтверждённый успешный cleanup повторно возвращает
сохранённый итог без Git и Herdr-команд: прежние ID после рестарта могут
принадлежать новому пользовательскому shell. Pending и failed восстанавливаются
по фактическому состоянию; уже закрытый таб или workspace не закрываются заново.
Terminal_id сохраняется из ответа создания layout до старта агента; явный
recover-layout подтверждает identity выбранной панели до запуска. Первый complete
и повторы проверяют её до Git и закрытия, без присвоения наблюдаемого терминала.
Замена терминала и старый запуск без сохранённой identity требуют сверки.
Для legacy с существующим layout сначала подтвердите его принадлежность
и сохраните работу. В Herdr вручную закройте подтверждённый таб задачи,
а принадлежащий ей временный workspace — целиком после отделения чужих панелей.
Проектные и родительские workspace сохраняйте. Затем complete проверит
отсутствие закрытого объекта без повторного удаления. Если принадлежность неизвестна,
сохраните layout до решения пользователя. Git worktree вручную не удаляйте.
Принадлежащий запуску временный Herdr workspace закрывается целиком, если
в нём только сохранённая панель. Workspace проекта и родительские workspace
репозиториев сохраняются. Другие табы сохраняют временный workspace;
cleanup.workspace_status объясняет причину. Для done в выбранном режиме branch
или с ранее зафиксированным push_branch любая чужая панель во всём workspace
останавливает complete ещё до Git-действий и cleanup, даже если исходный таб
уже исчез. Режим берётся из задачи и сохранённой Git-попытки, чтобы защитить
используемый checkout после смены режима и при повторе. После неизвестного исхода закрытия
повторный complete проверяет наличие workspace. Это не удаляет Git worktree:
его сохранение или удаление определяется таблицей Git-режимов выше.

## Сохранение без закрытия

По явному поручению reviewer команда `git-publish TASK --commit-message 'Describe the change'`
выполняет ту же Git-транзакцию, что complete, и оставляет задачу в review.
Таб, ревьюеры и worktree сохраняются во всех режимах таблицы выше.
Повтор сверяет дерево, локальную и удалённую ветки. Новые правки начинают
следующий цикл сохранения; незавершённая попытка с уже созданным commit
требует сначала устранить её ошибку. Auto требует актуального passed-ревью.
Complete после git-publish проверяет Git ещё раз и выполняет оставшийся cleanup.
Отмена после git-publish не отменяет уже выполненные merge/push.
