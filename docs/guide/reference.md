# Справка

Большинство действий можно поручать управляющему обычным текстом.
Для ручной проверки используйте CLI выбранного экземпляра.

## Основные команды

В примерах ниже control-workflow означает полный путь к установленной программе
с параметрами вашего экземпляра. Формат параметров — в [настройках](settings.md).

| Команда | Назначение |
| --- | --- |
| `environment` | Показать пути и выбранные настройки |
| `doctor` | Проверить зависимости и доступ к каталогам |
| `projects` | Показать проекты |
| `tasks --project ID` | Показать задачи проекта |
| `show tasks ID` | Показать постановку задачи |
| `open ID` | Открыть исполнителя выбранной задачи |
| `run RUN_ID --compact` | Показать состояние запуска |
| `answer ID --text 'Ответ'` | Передать ответ исполнителю |

Полная справка доступна через `control-workflow --help` и
`control-workflow КОМАНДА --help`. Команды публикации и приёмки применяйте
после проверки результата и явного решения пользователя.

## Если что-то не работает

**Агент не запускается.** Выполните doctor. Проверьте PATH, вход в CLI агента
и имя herdr-сессии. Наличие команды в doctor не подтверждает авторизацию.

**Навыки не видны управляющему.** Проверьте каталог управляющего и повторите команду skills из установки;
после добавления навыков перезапустите клиент агента.

**Неясно, запустилась ли задача после таймаута.** Попросите управляющего сверить
сохранённый запуск и фактический терминал. Повторный запуск без проверки может создать дубль.

**Не прошёл push или слияние.** Работа и worktree сохраняются. Сначала устраните
причину и проверьте состояние Git, затем повторите публикацию через управляющего.
Не удаляйте временный worktree вручную.

## Обновление

Попросите управляющего проверить доступное обновление панели. Перед установкой
остановите новые запуски и дождитесь завершения текущих команд и хода исполнителей.
Обновление сохраняет state, config и bindings. Уже запущенный процесс продолжает
использовать прежний бинарник: новая установка не перезапускает его автоматически.
